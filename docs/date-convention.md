# กติกาการจัดการวันที่ (Date Convention)

ใช้กับทุกหน้าและทุก API ของ CPA ที่มีช่องวันที่แบบ "วันที่อย่างเดียว" (ไม่มีเวลา) เช่น วันเกิด

## 1. หน้าเว็บ (vuewebui)

- แสดงและให้เลือกวันที่เป็นปี พ.ศ. รูปแบบ `วว/ดด/ปปปป` เช่น `15/03/2530`
- ปฏิทินของ date picker ต้องเป็นปฏิทินไทย
  - ปีบนหัวปฏิทินแสดงเป็น พ.ศ. ทั้งตอนเปิดดู ตอนกดเพิ่มลดปี และตอนพิมพ์ปีลงในช่องปี (พิมพ์ปีเป็น พ.ศ. แล้วต้องแปลงกลับเป็น ค.ศ. ก่อนส่งให้ flatpickr)
  - ชื่อเดือนเป็นภาษาไทยเต็ม เช่น มกราคม ชื่อวันใช้ตัวย่อ อา จ อ พ พฤ ศ ส
  - สัปดาห์เริ่มที่วันอาทิตย์ ใช้ locale ไทยของ flatpickr แบบ `{ ...Thai, firstDayOfWeek: 0 }` เพราะค่าตั้งต้นของ locale ไทยเริ่มวันจันทร์
- พิมพ์วันที่เองได้ (`allowInput: true`) โดยปีที่พิมพ์ถือเป็น พ.ศ.
- การแปลง พ.ศ. กับ ค.ศ. ต้องรวมไว้ใน helper กลาง (`toBE` / `toCE`) ทุกหน้าใช้ตัวเดียวกัน
- แปลงวันที่ด้วยวันที่ตามเวลาของเครื่องเท่านั้น ห้ามใช้ `toISOString()` หรือ `Date` แบบ UTC เพราะเครื่องที่อยู่ UTC+7 จะได้วันก่อนหน้าไปหนึ่งวัน

## 2. API และ database

- ส่งและรับวันที่เป็น ค.ศ. รูปแบบ `yyyy-MM-dd` ไม่มีส่วนเวลา
- backend ใช้ `DateOnly` (หรือ `DateOnly?` ถ้าไม่บังคับกรอก) ทุกชั้น ทั้ง entity, command และ view model ห้ามใช้ `DateTime`
- คอลัมน์ใน PostgreSQL ใช้ชนิด `date` (กำหนดใน `*Configuration.cs` ของ entity)

## 3. ช่องที่ไม่บังคับกรอก

- ถ้าเว้นว่าง หน้าเว็บต้องส่ง `null` ไป API ห้ามส่งสตริงว่างหรือวันที่ default อย่าง `0001-01-01`
- เปิดข้อมูลเดิมที่ไม่มีค่า ช่องต้องว่างและหน้าไม่ error
- ลบค่าที่มีอยู่แล้วบันทึก database ต้องเปลี่ยนเป็น `null`

## 4. วันเกิด

- ไม่บังคับกรอก
- ห้ามเกินวันปัจจุบัน และห้ามย้อนเกิน 120 ปีจากวันปัจจุบัน
- ถ้าพิมพ์ปีต่ำกว่าช่วงนี้ (เช่น เผลอพิมพ์ปี ค.ศ. `15/03/1987`) ให้ปฏิเสธและแจ้งว่า "กรุณากรอกปีเป็น พ.ศ."
- เช็กกฎนี้ทั้งสองฝั่ง
  - หน้าเว็บ ใช้ `minDate` (วันนี้ย้อนไป 120 ปี) กับ `maxDate: 'today'` ของ flatpickr
  - backend ใส่กฎเดียวกันใน validator ของ command (เช่น `CreatePatientCommand`, `UpdatePatientCommand`) เพราะคนที่เรียก API ตรงจะข้ามการเช็กของหน้าเว็บได้ และให้อ่านวันปัจจุบันจาก `TimeProvider` ที่ inject เข้ามา ไม่เรียก `DateTime.Today` ตรงๆ เพื่อให้ test ตรึงวันที่ได้

## 5. จุดที่ยังไม่ตรงกติกานี้

- entity `Services` เก็บ `BirthDate` และ `ChildBirthDate` เป็น `string` ยาว 20 ตัวอักษร ต้องแก้เป็น `DateOnly?` พร้อม migration ภายหลัง ก่อนแก้ต้องตรวจข้อมูลเดิมว่าเก็บปีเป็น พ.ศ. หรือ ค.ศ. และใช้รูปแบบอะไร เพราะถ้าปนกันจะแปลงคลาดไป 543 ปีโดยไม่มี error
