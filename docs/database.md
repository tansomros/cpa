## Database Convention

Database Convention คือข้อตกลงร่วมกันในการออกแบบโครงสร้างฐานข้อมูล (Database Schema) เพื่อให้การจัดเก็บข้อมูลมีความเป็นระบบ ขยายระบบได้ง่ายในอนาคต และทำงานร่วมกับเครื่องมืออย่าง Entity Framework Core (EF Core) ได้โดยไม่มีปัญหาติดขัด [1, 2, 3, 4] 
นี่คือหัวข้อสำคัญสำหรับฐานข้อมูลประเภท Relational Database (เช่น SQL Server, PostgreSQL, MySQL) ที่ทีมควรใช้ร่วมกันครับ:
------------------------------
## 1. การตั้งชื่อตาราง (Table Naming Conventions)

* ใช้คำนามพหูพจน์ (Plural): เนื่องจากตารางทำหน้าที่เก็บ "กลุ่ม" ของข้อมูลชนิดนั้นๆ
* ตัวอย่าง: Customers, Orders, Products
* รูปแบบตัวอักษร: เลือกใช้ระบบใดระบบหนึ่งให้เหมือนกันทั้งฐานข้อมูล
* PascalCase (นิยมมากใน SQL Server): CustomerAddresses
   * snake_case (นิยมมากใน PostgreSQL): customer_addresses [5, 6, 7, 8] 
* ตารางความสัมพันธ์ (Join Table/Bridge Table): สำหรับความสัมพันธ์แบบ Many-to-Many ให้ใช้ชื่อตารางสองตัวมารวมกัน
* ตัวอย่าง: StudentCourses (ตารางกลางเชื่อมระหว่าง Students และ Courses) [9, 10, 11, 12, 13] 

## 2. การตั้งชื่อคอลัมน์ (Column Naming Conventions)

* คีย์หลัก (Primary Key - PK): แนะนำให้ใช้คำว่า Id สั้นๆ หรือ [TableName]Id
* ตัวอย่าง: Id หรือ CustomerId (ประเภทข้อมูลควรใช้ int, bigint หรือ uniqueidentifier/UUID) [14, 15, 16, 17, 18] 
* คีย์นอก (Foreign Key - FK): บังคับใช้รูปแบบ [TargetTableName]Id เพื่อให้เดาความสัมพันธ์ได้ทันที
* ตัวอย่าง: CustomerId ในตาราง Orders เพื่อบอกว่าออเดอร์นี้เป็นของลูกค้าคนไหน
* คอลัมน์สถานะ (Boolean/Status Flags): ให้ขึ้นต้นด้วยคำกริยา เช่น Is, Has, Can
* ตัวอย่าง: IsActive, HasVerified, CanDelete

## 3. คอลัมน์มาตรฐานสำหรับติดตามข้อมูล (Audit Columns)
ทุกตารางหลักในระบบ ควรมี 4 คอลัมน์นี้อยู่ท้ายตารางเสมอ เพื่อใช้ตรวจสอบว่าใครทำอะไรกับข้อมูลตอนไหน:

* CreatedAt (DateTime / DateTimeOffset): วันเวลาที่สร้างข้อมูล
* CreatedBy (nvarchar/varchar): ไอดีหรือชื่อของผู้สร้าง
* UpdatedAt (DateTime / DateTimeOffset - Nullable): วันเวลาที่มีการแก้ไขล่าสุด
* UpdatedBy (nvarchar/varchar - Nullable): ไอดีหรือชื่อของผู้แก้ไขล่าสุด [19, 20] 

## 4. การจัดการกรณีลบข้อมูล (Deletion Convention)

* Soft Delete (แนะนำสำหรับข้อมูลสำคัญ): ห้ามใช้คำสั่ง DELETE จริงออกจากฐานข้อมูล แต่ให้ใช้คอลัมน์ IsDeleted (Boolean) และ DeletedAt เพื่อซ่อนข้อมูลแทน เผื่อกรณีที่ต้องกู้คืนข้อมูลในภายหลัง
* Hard Delete: ใช้เฉพาะกับตารางที่เป็นข้อมูลชั่วคราว ข้อมูลล็อก หรือ Log ที่มีอายุการใช้งานจำกัดเท่านั้น [21, 22, 23] 

------------------------------
## 5. การกำหนดประเภทและขนาดข้อมูล (Data Types Rules)

* จำกัดความยาวสตริงเสมอ: ห้ามปล่อยให้ฟิลด์ตัวอักษรเป็น nvarchar(max) หรือ text โดยไม่จำเป็น เพราะจะทำให้ฐานข้อมูลทำงานช้าและกินพื้นที่ ให้กำหนดขนาดที่เหมาะสมเสมอ
* ชื่อ-นามสกุล: nvarchar(150)
   * อีเมล: varchar(255) (ใช้วิธีเก็บแบบ varchar เพราะอีเมลไม่มีอักษรภาษาไทย ประหยัดพื้นที่ได้ครึ่งหนึ่ง)
   * เบอร์โทรศัพท์: varchar(20) [24, 25, 26, 27] 
* เก็บจำนวนเงิน (Money/Currency): ห้ามใช้ float หรือ double เพราะอาจเกิดปัญหาเลขทศนิยมคลาดเคลื่อนเมื่อคำนวณ ให้ใช้ประเภท decimal(18,2) (หรือความละเอียดตามธุรกิจ) เสมอ [28, 29] 

## 6. การทำดัชนี (Indexing Rules)

* คอลัมน์ที่เป็น Foreign Key (FK) ควรทำ Index เสมอ เนื่องจากเป็นจุดที่ต้องใช้ในการ Join ตารางบ่อยที่สุด ช่วยให้คิวรีเร็วขึ้นมหาศาล
* คอลัมน์ที่ถูกใช้ในเงื่อนไขการค้นหาบ่อยๆ (เช่น Email, Username, OrderNumber) ควรทำ Unique Index หรือ Index มารองรับ [30, 31, 32, 33, 34]
